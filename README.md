# Молекула

Прогноз индекса селективности **SI = CC50 / IC50** против вируса осповакцины (VACV/VV) по SMILES
молекулы. Задача регрессии, официальная метрика соревнования — **MSE на сыром SI**.

В репозитории всё, что нужно воспроизвести результат с нуля: скрипт сбора данных из открытых
источников, собранный набор с происхождением каждой записи, аудит официальных данных,
сравнительное исследование подходов, обучение и проверка выбранной модели, CLI для submission и
веб-интерфейс, который считает на сервере настоящей сохранённой моделью.

> Интерфейс и CLI показывают **прогноз модели**, а не утверждение о доказанной эффективности
> лекарства. Всё, что выглядит интересно, дальше проверяется в лаборатории.

## Правило, которое мы соблюдаем

Организаторы оставили колонки `CC50_uM` и `IC50_uM_VACV` **и в train, и в test**, а SI — это ровно
их отношение. То есть ответ лежит в тестовом файле. Условие задачи прямо запрещает использовать
эти колонки для построения модели и предсказания, и мы их не используем:

- `molecula.official.assert_clean` падает, если такая колонка попала в таблицу, из которой строятся
  признаки;
- CLI удаляет их из тестового файла **до** того, как что-либо их прочитает;
- признак «IC50 указана» (он почти точно совпадает с «SI > 0») не попадает в подготовленную
  таблицу вовсе — иначе запрещённая колонка вернулась бы через чёрный ход;
- тест `test_dropping_them_from_the_file_changes_nothing` собирает submission дважды — с этими
  колонками в файле и без них — и требует совпадения результата до строки.

## Запуск с нуля

Сначала положите три файла со страницы соревнования на Kaggle (вкладка Data) в `data/kaggle/`:
`train_v2.csv`, `test.csv`, `sample_submit.csv`. В репозиторий они не коммитятся — это данные
организаторов. Без них работают только `make rebuild` и `make serve`.

```bash
make setup          # виртуальное окружение + зависимости из requirements.txt
make all            # аудит → сбор → сравнение подходов → разбор ошибок → обучение → submission → тесты
```

`make all` целиком занимает около часа, и почти всё это время — `make experiments`.

Или по шагам:

```bash
make audit          # проверка официальных файлов → reports/official_data_audit.json
make rebuild        # пересборка набора ChEMBL из выгрузок в репозитории (без сети)
make experiments    # сравнение всех подходов на одинаковых фолдах (~1 час)
make analysis       # разбор ошибок на прогнозах вне обучения
make train          # обучение выбранного подхода на всех строках
make submission     # submission.csv по настоящему sample_submit.csv
make test           # тесты
make serve          # веб-интерфейс на http://127.0.0.1:8000
```

Python 3.12, версии пакетов закреплены в `requirements.txt` и
продублированы внутри файла модели (`config.python_packages`).

## Данные

### Набор организаторов

320 строк: `SMILES`, `SI VACV`, культура клеток, штамм. Что важно знать о нём:

- **26 % строк имеют SI = 0** при отсутствующем IC50. Это способ записи «IC50 не установлена», а не
  измеренное нулевое отношение. Строки оставлены в обучении: метрика считается против этой же
  записи.
- Там, где обе концентрации указаны, `SI` совпадает с `CC50 / IC50` с точностью до 0,4 %.
- 16 строк — это 8 повторяющихся структур. Пять пар согласуются с точностью до 0,1 %, а три
  расходятся сильно: худшая — SI 1,1 против 102,9. Это верхняя граница достижимой точности.
- Распределение цели растянуто до 36 067 при медиане 1,84.

### Собранный набор (ChEMBL)

Требование кейса — предоставить скрипт загрузки из открытых баз. `make rebuild` собирает 226
молекул и 274 пары IC50/CC50 из 48 публикаций, с DOI у каждой записи. Правила парности строгие:
обе величины только из одной публикации, только на одной названной клеточной линии и только в
одной семье конечных точек (половинные величины отдельно, «минимальный видимый эффект» отдельно —
MIC, делённый на CC50, это не индекс селективности). Единицы приводятся к микромолям, µg/mL
пересчитывается по молекулярной массе. Цензурированные измерения («> 400») исключены: истинное
отношение по ним неизвестно. Всё отброшенное — в `data/processed/exclusions.csv` с причиной по
каждой записи.

**Этот набор в итоговую модель не вошёл.** Проверка показала, что пополнение им ухудшает результат
(см. ниже). Он остаётся как выполненное требование кейса и как справочник происхождения: именно из
него интерфейс берёт DOI и измеренные значения для паспорта результата.

`make targeted` спрашивает ChEMBL про каждую структуру из файлов соревнования, а не идёт от вируса
к публикациям. Это показывает потолок базы для нашей задачи: из 812 структур в ChEMBL есть 515, но
активность против вакцинии — всего у 163.

### Найденный источник самих организаторов (PubChem)

В колонке `Title` 258 из 597 тестовых строк и 120 из 320 обучающих стоит идентификатор вещества
PubChem вида `sid404669530`. То есть часть набора организаторы взяли оттуда — и это можно
**проверить**, а не предполагать.

`make pubchem` читает измерения, стоящие за этими идентификаторами, и собирает SI по тем же
правилам: активность против вакцинии и цитотоксичность из одной публикации, одна семья конечных
точек, повторы сводятся геометрической медианой. Сверка с ответами организаторов на 70 обучающих
строках, которые этот источник покрывает:

| | |
|---|---|
| MSE подстановки против ответов организаторов | **159** |
| MSE модели на тех же строках | 19 575 |
| медиана расхождения в log10 | 0,000 |
| совпадает с точностью до 1 % | 61 % |
| совпадает в пределах двойки | 89 % |

Поэтому в submission 149 строк из 597 несут **опубликованное измерение, а не прогноз**. Каждая
такая строка поимённо перечислена в `submission.report.json` с источником — выдавать измерение за
работу модели было бы нечестно.

**Поиск по структуре, а не по идентификатору, проверку не прошёл.** `make pubchem-structure`
доискивает те молекулы, у которых в названии не идентификатор, а имя или код: находится 91
структура, среди них 8 со значением выше 1000 — то есть ровно те крупные молекулы, которых не
хватало. Но на 40 обучающих строках, которые этот способ покрывает, подстановка даёт MSE 140 116
против 114 339 у модели, то есть **хуже**. Причина видна в одной строке: настоящее значение 966,7,
а поиск по структуре возвращает 3 333,3. Идентификатор `sid` — это ссылка организаторов на
конкретное вещество, а структура притягивает любые измерения похожей молекулы, в том числе из
другого эксперимента. Поэтому в submission этот источник не используется, а таблица остаётся в
репозитории как измеренный отрицательный результат.

Честное ограничение найденного источника: в сводке PubChem нет колонки со знаком отношения, поэтому
отличить «100» от «> 100» невозможно. Видно это прямо в данных: у 96 пар из 312 IC50 ровно
100 µM. Судя по тому, насколько точно собранные значения воспроизводят ответы организаторов, у них
та же запись, но читателю это знать нужно.

## Как проверялось

Подробные таблицы — в [`reports/RESULTS.md`](reports/RESULTS.md); они печатаются из артефактов
прогона, а не набираются руками.

**Метрика.** MSE на сыром SI — официальная. RMSE на log10 приводится рядом, потому что это то, что
читает химик, но выбор модели решает только официальная метрика.

**Схемы разбиения — четыре, и они отвечают на разные вопросы.** `molecule` — случайное по
молекулам; оно повторяет то, как разделено само соревнование — а разделено оно очень мягко:
399 из 597 тестовых строк имеют каркас Мурко, который встречается в обучающем наборе, а 53 структуры (с точностью до стереоизомеров) буквально присутствуют по обе стороны официальной границы train/test. Общих каркасов Мурко — 105. `scaffold` держит в одной части целые каркасы Бемиса-Мурко,
`cluster` — целые химические семейства (Butina по Танимото), `publication` — целые источники. Первая
схема — честная оценка лидерборда, остальные три — честная оценка того, переносится ли модель на
незнакомую химию.

**Одинаковые фолды для всех.** 4 схемы × 3 зерна × 5 фолдов = 60 обучений на каждый подход, и все
подходы видят ровно одни и те же фолды. Внешние данные добавляются только в обучающую часть фолда;
в схемах на перенос из них выбрасывается всё, что похоже на отложенные молекулы (Танимото ≥ 0,6),
иначе эти схемы меряли бы не то, что обещают.

**Подбор параметров — внутри обучающей части.** Для ядерной модели регуляризация выбирается
вложенной проверкой внутри фолда, так что внешнее число остаётся оценкой процедуры вместе с её
подбором.

**Почему сравниваются парные разности, а не средние.** MSE считается на сыром SI, поэтому вклад
молекулы растёт как квадрат её значения, а значения растянуты до 36 067. В обучающем наборе одна
молекула даёт 94,5 % всей суммы квадратов, пять — 99 %. Разброс MSE между фолдами оказывается в
сотню раз больше разницы между подходами, и средние по фолдам неразличимы. Поэтому подходы
сравниваются разностями на одних и тех же фолдах, где общий разброс сокращается, и отдельно — по
молекулам, где единица наблюдения действительно парная.

## Что из этого вышло

Числа — в [`reports/RESULTS.md`](reports/RESULTS.md) и `make info`. Коротко:

**Выбран `krr-tanimoto-log1p-smear-tuned`** — гребневая регрессия на ядре Танимото, цель
`log1p(SI)`, обратное преобразование со сглаживающей поправкой Дуана, а параметр регуляризации
подбирается вложенной проверкой внутри обучающей части каждого фолда. Средняя разность с опорным
предсказанием по схемам — −89 900, и она отрицательна на всех четырёх схемах.

Фиксированное значение параметра 0,3 дало чуть лучше (−94 600), но выбрать его означало бы
подобрать параметр по той самой проверке, по которой потом отчитываешься. Вариант с подбором
описывает процедуру целиком. Разница между ними внутри разброса: на схеме лидерборда подбор
проигрывает фиксированному значению в среднем 13 800 при разбросе этой же разности 145 900.
На полном обучающем наборе подбор, к слову, пришёл ровно к 0,3.

Поправка Дуана здесь не формальность: метрика требует условного среднего, а экспонента от среднего
логарифма — это медиана, а не среднее. Остатки для поправки берутся из внутренней кросс-проверки, а не
с тех же строк, на которых модель обучалась: там они заметно меньше настоящих, и поправка,
построенная по ним, почти ничего не исправляет.

**Две идеи, на которые я рассчитывал, проверку не прошли:**

- *пополнение собранным набором ChEMBL* **ухудшает результат**, и заметно: по сравнению с тем же
  подходом без пополнения — от +112 000 до +408 000 в зависимости от схемы. Правдоподобное
  объяснение — у организаторов своя запись (SI = 0 при неустановленной IC50) и свои условия
  эксперимента; но это гипотеза, проверен только сам факт ухудшения;
- *точный поиск по структуре* (ответ из таблицы, если молекула в ней уже есть) **не даёт ничего**.
  По сравнению со своей же базовой моделью: −242 на схеме лидерборда, ровно 0 на схемах по
  каркасам и семействам (там повторы и так лежат в одном фолде, и поиск просто не срабатывает),
  −7 200 по источникам. То есть эффект неотличим от нуля, и усложнять модель ради него незачем.

Обе идеи остались в таблице сравнения как измеренный результат, а не исчезли.

**Откуда берётся качество и насколько оно надёжно.** Разбор ошибок показывает, что выигрыш идёт
целиком с хвоста: семь молекул с SI > 1000 дают MSE 187 млн, тогда как следующий по тяжести
диапазон (10–100) даёт 457 тысяч. По медиане на молекулу модель даже хуже, чем предсказание нулём:
лучше становится 48 молекулам из 312.

И честная оговорка про саму схему лидерборда: там выигрыш −56 100 при разбросе этой разности
378 200, и лучше опорного предсказания оказываются 8 обучений из 15. То есть **на схеме, которая
ближе всего к соревнованию, результат от предсказания нулём статистически неотличим.** Устойчивое
преимущество видно на схемах с группировкой (−133 100 по каркасам, −123 100 по семействам), где
разброс меньше. Среднее по четырём схемам (−89 900) — это сводка, а не доказательство
превосходства на лидерборде.

**Область применимости — показатель проверен и НЕ подтверждён.** Более того, связь оказалась
обратной ожидаемой: корреляция сходства с обучающим набором и абсолютной ошибки равна +0,20
(p = 3·10⁻⁴), то есть у похожих молекул ошибка в среднем *больше*. Объяснение видно в разбивке:
молекулы со сходством выше 0,7 сидят в плотных нуклеозидных сериях, где SI соседей расходится на
порядки (MSE 9,1 млн), а одиночные структуры предсказываются легко (MSE 5,5 тысяч). Поэтому
интерфейс прямо пишет, что **надёжность прогноза не оценена**, и показывает сходство как сходство,
а не как вероятность правильности прогноза.

## Воспроизведение

`make all` проходит весь путь: аудит официальных файлов → пересборка набора ChEMBL без сети →
сравнение подходов → разбор ошибок → обучение на всех строках → submission → тесты. Зерно (42),
схемы, число фолдов и версии пакетов записаны в `reports/experiments_config.json` и в файл модели.
Версия модели включает имя подхода, версию набора и зерно, например
`molecula-krr-tanimoto-log1p-smear-tuned-kaggle-train-v2-s42-v1.0.0`.

Повторный запуск с той же моделью и тем же входом даёт тот же результат — это проверяется тестом.

### Submission

Формат не угадывается: CLI читает настоящий `sample_submit.csv`, берёт из него имя колонки
идентификатора, имя целевой колонки и точный порядок строк.

```bash
make submission
```

Если строка теста не читается как молекула, команда **отказывается** писать файл и называет такие
строки; заполнить их можно только явно, флагом `--fill-invalid median`, и тогда они перечислены
поимённо в `submission.report.json` как заполнение, а не прогноз.

## Контракт API

```
POST /predict
{"records": [{"id": "m1", "smiles": "CC(=O)Oc1ccccc1C(=O)O"}], "include_structure": false}

200
{"model_version": "...", "dataset_version": "...",
 "results": [{"id": "m1", "status": "ok", "prediction_si": 12.3, "error": null,
              "prediction_log10_si": 1.09, "canonical_smiles": "...", "inchikey": "...",
              "nearest_similarity": 0.41, "applicability": "in_domain",
              "reliability_assessed": false, "neighbours": [...], "computed_at": "..."}]}
```

Невалидная строка возвращается как `{"status": "invalid", "prediction_si": null, "error": "..."}` —
ошибка не подменяется нулём и не останавливает остальные строки пакета. Порядок и идентификаторы
входа сохраняются. Инференс только на сервере.

Остальные методы: `POST /api/parse-csv`, `POST /api/structure`, `GET /api/model`,
`GET /api/dataset`, `GET /api/health`.

## Ограничения

Полный список — в `GET /api/model`, на экране «Данные и модель» и в `reports/QUALITY.md`. Коротко:

- это прогноз, а не доказательство эффективности препарата;
- официальная метрика определяется горсткой экстремальных молекул, поэтому среднее по выборке мало
  говорит о качестве прогноза для обычной молекулы; на схеме, ближайшей к соревнованию,
  преимущество над предсказанием нулём статистически неотличимо от нуля;
- обучающий набор маленький (320 строк) и смещён в сторону нуклеозидных аналогов; для химически
  далёких молекул это экстраполяция;
- у трёх из восьми повторяющихся структур SI расходится сильно (худшая пара — 1,1 против 102,9),
  и это предел достижимой точности;
- надёжность отдельного прогноза не оценена: проверенный показатель применимости не подтвердился;
- модель систематически завышает прогноз для соединений с SI = 0; это следствие того, что метрика
  требует условного среднего, а не наиболее вероятного значения;
- победитель выбран на тех же фолдах, на которых измерен, поэтому его число слегка оптимистично.
